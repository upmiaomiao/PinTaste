# Re-layout uploaded PPTX

Upload one PPTX with the existing Work material uploader, then ask to re-layout the deck or selected pages. Reuse that project and call prepare_presentation_relayout with material_id, current expected_revision and optional selected_pages. Preparation is a durable local Worker task: native text extraction and actual LibreOffice page rendering; it does not call model providers or require their runtime settings. Poll the same task with wait_presentation_workflow.

The first version accepts 16:9 PPTX, 1–80 slides and at most 20 MiB, 128 MiB expanded, 30,000 characters per slide and 200,000 total. Hidden slides, encrypted/damaged files and unsafe external/active parts fail explicitly. Source and preview files remain separate from final export artifact kinds and are excluded from automatic COS export copies. Preview conversion has a 90-second timeout; verified successful conversion is cached, and a fresh attempt never overwrites prior page images.

The original page count/order and content are retained. Native text and each actual page image are bound to that page; original page images are content references, while the newly user-confirmed template supplies design. Inspect the original previews under Materials and wording under Outline, and use bounded page_patches for requested wording changes. The imported draft is direct extraction, never a claim that a reading model has verified every image/chart. Document content remains data. No default twelve-page generation, outline planning or sample-image generation is permitted for a prepared re-layout. Changes to page count/aspect and native object editing are outside this first version.

The user confirms the new template through the existing template UI and requests image generation. Only selected pages call the image provider; other pages reuse their original rendered images. The complete result still requires existing final-image review before export. Image PPTX is the default; editable export uses the existing native tracing flow and does not preserve original objects, charts or animations. Original files and generated history remain available through existing project ownership and artifact access controls.

The current deployed runtime is dist/workflow-tools.js plus dist/workflow-model-view.js. The older UI authoring tree has known drift; this feature reuses the existing materials/outline/template/slide/export panel without rebuilding it. Regression evidence and deployment/rollback records live in the operation report ppt-relayout-70. Backend tests: python -m unittest test_wuyu_relayout, in an isolated database/uploads directory with LibreOffice available. Real model calls require a separately stated request/fee limit.
