# Agent Note: PPT 材料容量与所有者确认删除

Status: implemented

[English](2026-11-05-ppt-material-capacity-and-deletion.md) | 中文

## 问题

单文件和单批上传限制无法约束项目累计提取数据。材料正文过大可能在模型预算生效前阻塞阅读准备。所有者还需要永久删除上传原文件，同时保留已生成的演示文稿。

## 决策

后端限制每项目最多 50 个上传文件；默认累计上传 500 MiB、提取 2,000,000 字符、10,000 个文字片段、1,000 个来源图像和 24 MiB 序列化解析材料。解析使用项目剩余容量，截断提取不能标成完整。阅读准入在模型调用前检查选用证据；准备阶段有协作式 60 秒截止。原有调用、积分、并发、取消及缓存规则继续生效。

详情面板沿用私人 iframe 到 Host 的请求通道执行 `delete_material`。Host 绑定挂载的项目句柄、校验精确字段并协调 Session 上传队列。Cookie 认证后端要求项目归属、明确确认、当前版本及幂等标识。该操作不是模型工具或工作流动作。其他管理员也不能通过此入口删除所有者材料。

项目任务进行中拒绝删除。乐观事务移除材料和 ReferenceFile、使阅读及相关草稿失效，并在既有工作流 JSON 记录待清理状态。清理完成前阻止新处理和上传。路径仅限所属项目的材料、预览、来源资产和阅读目录，拒绝符号链接与生成成果路径。物理清理可以重试。完成记录数量有界，不保留材料正文、文件名或路径。

选中原文件和解析预览被清除，同时清除可能混合多份来源的项目共享阅读缓存及草稿。其他上传原文件、已生成 PPT 及导出和对话历史保留。上传队列释放已删除的完成行，仅重新绑定剩余未发送材料，不上传文件或发送消息。

## 考虑过的替代方案

**仅排除材料。** 排除适用于控制阅读范围，但保留原文件及解析内容，不能满足永久删除。

**只清除选中来源的缓存。** 共享综合结果和阅读草稿可能引用多份来源，清除全部阅读缓存可避免这些衍生文件继续保留已删除材料。

**将删除开放为模型工具。** 既有用户专用 iframe 请求通道已有项目绑定，无需在破坏性操作中依赖尚未验证的 MCP 工具可见性过滤。

**允许处理中删除。** 进行中的解析或阅读可能重新写回已删除内容，准入和待清理阻塞防止该竞争。

**仅增加模型上下文。** 模型容量无法约束本地项目 JSON、提取内存或阅读准备。

## 后果

确认文字明确永久删除、阅读草稿失效，以及保留已生成 PPT 和对话历史。对话历史中先前引用的内容不会清除。删除一份材料后须重新确认受影响草稿。没有数据库结构迁移或云存储变更。

容量和准备截止约束准入及协作式执行，不强制终止原生解析线程。已有大项目仍可读取和管理，超限选用证据在调用模型前返回明确处理建议。

验证用临时 SQLite 和真实临时文件检查删除及导出保留，用实际客户端业务模块检查请求与队列，用实际 SDK Host 和面板检查中英文取消、确认、任务忙碌、清理重试、容量错误及窄屏布局。完整框架 GUI/回放命令被现有依赖安装配置阻断，基线与候选均有相同 25 项 TypeScript 错误。这些检查不代表付费 PPT 生成或原生解析负载测试。
