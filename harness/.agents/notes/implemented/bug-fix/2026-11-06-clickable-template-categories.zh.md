# Agent Note: 两处模板浏览入口的可点分类

Status: implemented

[English](2026-11-06-clickable-template-categories.md) | 中文

## 问题

工作对话面板和项目详情应用是两个独立模板浏览入口。只给一处增加分类，另一处仍会显示难查找的长列表；Host桥接若丢弃分类参数，即使界面有控件也不能筛选。

## 决策

两处入口均展示“全部”及整套PPT、工艺流程图、技术路线、摘要图、论文方法图五类按钮。标签跟随界面语言，请求保留服务端稳定的中文分类值。分类、账号私有/公共来源和搜索共同进入既有鉴权列表操作。切换分类重置偏移，24条分页保留全部条件。加载时隐藏上一类卡片，空结果和失败分别显示列表状态，重试使用当前条件。读取和切换分类不确认模板，也不启动模型。

项目详情的postMessage桥接将已校验分类传入既有列表执行器。受信任的single_image参考只有在reference_sufficient仍为true时才允许一张已实际加载预览；普通整套保持既有多页门槛。

详情应用运行产物由[template-category-ui.cjs](../../../../../work-agent/tools/template-category-ui.cjs)基于SHA锁定的已部署HTML生成。生成器定点修改五个已知函数并加入分类辅助代码，不重建较旧的authoring目录。React组件采用相同分类值并保留原确认操作。

## 考虑过的替代方案

**只在一处保留下拉框。** 另一处仍无筛选，分类选项也不直接可见。

**仅筛选当前加载页。** 会漏掉其他页的匹配条目，并显示错误总数。

**重建旧详情应用authoring目录。** 可能覆盖目录尚未包含的线上材料、研究、历史和本地化行为。

## 影响

“全部”保留未分类的私人上传，具体分类不包含没有该分类的记录。筛选只改变查看状态，不更改项目已选模板或生成文件；归属校验和模板使用范围仍由服务端执行。本决策不改变SQL结构、模型配置、共享库内容或云策略。

定向验证通过真实客户端与详情应用代码观察分类传递、来源/搜索组合、分页、迟到响应、空结果/错误恢复和双语窄屏显示。完整框架类型/GUI检查、所有模型兼容性和付费生成是独立覆盖限制；本文不声明这些检查通过。
