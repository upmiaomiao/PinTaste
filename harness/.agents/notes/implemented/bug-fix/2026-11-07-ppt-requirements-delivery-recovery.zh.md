# Agent Note: 图片优先交付后的PPT需求恢复

Status: implemented

[English](2026-11-07-ppt-requirements-delivery-recovery.md) | 中文

## 问题

工作流先交付已审核页图，再按需转换为可编辑文稿，因此运行时输出格式可能不同于对话保存的交付偏好。把该运行字段当作规划需求，会误报投影待同步。不同观察状态复用同一投影请求ID，还可能与旧回执冲突。当前需求卡片读取失败后，需要通过明确的权威回读恢复视图。

## 决策

对话继续拥有输出偏好，brief投影比较规划字段及配置版本标记。输出偏好不强制覆盖运行brief的交付状态。模型直接改写受管brief字段仍受限制，可编辑导出保留独立确认、页图审核与执行检查。

投影请求身份包含对话版本、项目身份、观察到的工作流版本及稳定补丁指纹。重试同一观察操作时身份不变，后续状态或不同补丁使用不同身份。

成功读取归属项目后，只有投影内容及配置标记一致，才能确认原有待同步状态。不同绑定、无效或较旧的工作流版本、并发改变的需求版本均不能被确认。该确认只更新同步元数据，不修改已保存偏好或项目内容。真正发生模板确认变化时，保留既有同步路径。读取失败仍可展示已保存需求，但不声称确认成功。

工具卡片通过已注册操作区分读取失败和更新失败。点击“查看当前需求”会明确重新加载权威控制器，错误或冲突状态下也可执行。历史失败结果仍保留失败含义，工具结果文字不构成另一份配置。

## 考虑过的替代方案

**把可编辑偏好强制写入每次工作流brief。** 图片优先交付会不断覆盖该值，并混淆偏好与转换执行。

**读取时无条件清除待同步状态。** 真正的内容差异、旧配置标记或归属读取失败也会被误报为已应用。

**每次重试使用随机投影请求ID。** 响应不确定时可能重复执行同一操作，无法复用已有回执。

## 影响

匹配的原项目可以在原对话恢复，无需新模型请求或重建项目。真正不一致的内容仍保持待同步，已保存的可编辑偏好仍须通过明确导出流程执行。针对持久存储、Loader及客户端控制器的定向测试覆盖这些边界。本次不增加失败模型任务的自动重试，也不修复其他材料、供应商或原生解析器故障。
