# Agent Note: 在原PPT项目中恢复并避免重复阅读

Status: implemented

[English](2026-11-07-ppt-project-recovery.md) | 中文

## 问题

改成一页时可能仍保留执行层不接受的整套类型。相同的重新规划动作可能反复读取同一份坏内容计划缓存，而调整计划的反馈又会改变全部reader缓存身份。通用冲突提示掩盖了在原项目继续所需的审核或纠正步骤。

## 决策

需求owner在既有事务内把deck加一页解析为pages加一页。来源和字段版本跟随已接受的更新，幂等仍基于原始请求，调用者的补丁对象保持不变。非法组合不写需求或回执。

规划反馈属于综合规划，不属于来源阅读。只有来源身份、角色、哈希、排除范围和阅读目标保持兼容时，工作流才保留精确reader brief。历史reader输入仍可使用，阅读目标或来源范围变化时不能继承无关上下文。真实来源和缓存完整性检查仍有最终约束。后续规划可以继续使用反馈，但反馈不授权访问新来源。

既有raw缓存中的已知确定性内容计划校验失败使用明确的坏缓存恢复分类，并保留安全子错误码。raw响应保留供诊断，相同输入不自动派发新的付费请求；对话等待具体反馈后再修改当前草稿。来源、路径和缓存包装完整性失败不能降级成普通计划纠正问题。

MCP恢复合同将一组明确业务码映射为固定解释与下一步。草稿、模板、研究审核、并发和额度问题分别保留。未知错误仍为失败，不回显后台正文，也不虚构版本冲突。回读和错误展示不批准草稿、不改模板、不重试付费任务。图片优先交付的可编辑导出保留独立明确请求与审核合同。

## 考虑过的替代方案

**先保存组合，再由投影拒绝。** owner会确认一个不能执行的状态，普通一页要求看起来就像服务故障。

**缓存校验失败后自动重复综合规划。** 既可能未经新决定重复付费，又没有改变输入来纠正坏计划。

**把所有反馈放入reader输入。** 仅修改文稿结构也会舍弃有效提取结果，重复阅读全部未变材料。

**不核对范围就复用reader。** 来源或阅读目标变化后可能静默使用无关证据，并越过原有完整性检查。

## 影响

一页更新与具体计划纠正可以在原项目继续，来源、成功工作与历史成果保留。范围和哈希变化仍使相关工作失效。owner格式及数据库结构不变，不批量重写历史业务数据；模型、搜索、模板、页图、导出、额度和删除权限沿用既有检查。

定向owner、HTTP、Loader、MCP和后端缓存测试使用自制数据与模拟外部provider验证这些合同，不代表真实模型质量、付费重试费用或高负载故障恢复已验收。全局授权、重复收费任务准入、语言政策、进程隔离与存储是独立工作。
