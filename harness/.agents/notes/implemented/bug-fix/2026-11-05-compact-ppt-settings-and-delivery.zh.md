# Agent Note: 紧凑PPT设置与延后交付选择

Status: implemented

[English](2026-11-05-compact-ppt-settings-and-delivery.md) | 中文

## 问题

展开的聊天区配置卡将未来页数/语言偏好和输出决定混在一起。旧可编辑默认值可能在页图审核后立即启动原生转换。交付面板缺少明确格式选择，强制中文的模型指令也与英文内容设置冲突。

## 决策

紧凑按钮打开原生弹层，配置页数和内容语言。应用保存既有对话记录，不启动任务。Escape、点击外部和焦点恢复由浏览器处理，窄屏显示底部面板。非法页数和保存错误保持可见。旧输出字段兼容读取，但不在聊天区或注入摘要中出现。明确输出要求保留为普通对话请求，不保存成新默认值。

自动续跑首次到达描摹边界时先交付已审核页图及本地图片PPTX，即使旧偏好是可编辑。已启动原生批次保留恢复路径；明确导出可编辑版仍可排队转换。交付面板通过既有人工审阅的对话草稿路径提供图片PPTX、可编辑PPTX、PDF和图片ZIP。点击选择不调用工具或授权付费操作；可编辑请求要求转换前说明新增调用上限和预计费用。

模型写作策略跟随请求的内容语言。英文规划使用英文长度规则，生图提示要求保留已确认文字的语言。实际iframe以SHA锁定转换器修改。[私人模板决策](2026-11-05-private-upload-template-library.zh.md)仍然有效。

## 考虑过的替代方案

**仅隐藏输出选择器。** 仍会保留隐藏的可编辑默认值及自动转换。

**修改全部已保存偏好。** 无需数据迁移，兼容读取和更改请求行为即可。

**格式按钮直接生成。** 会绕开既有对话审阅和费用确认边界。

## 后果

无需数据库结构迁移、重写现有项目、外部模型调用或云端写入。后续自动续跑仅在已审核页图边界更改交付偏好，现有文件仍可下载。输出选择仍需确认产生的对话请求。真实付费英文生图和可编辑整稿验收不属于本次零调用验证。

检查覆盖偏好兼容与数量限制、首次和已启动原生交付、明确导出排队、捕获的英文生图请求、中英文实际工作台，以及实际SDK格式选择消息。完整框架检查沿用已记录的依赖环境限制。
