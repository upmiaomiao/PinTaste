# Agent Note: 研究失败后在原项目恢复

Status: implemented

[English](2026-11-06-ppt-recovery-and-search-mode.md) | 中文

## 问题

公开检索词计划失败时，PPT准备可能在尚未取得来源前停止。通用失败提示没有提供回到上传材料的可执行路径，助手可能因此把项目描述为永久锁死。搜索开关在发送后清空，也让连续请求反复要求用户选择同一模式。

## 决策

受信任的工作流结果为没有保留来源的失败或暂停研究提供原项目恢复选项。真实用户点击后，通过既有研究确认操作选择现有材料。点击读取当前研究与工作流状态，要求版本一致、没有当前待处理任务，再按版本提交。问题已变更、有活动任务或保留报告与来源时拒绝这条快捷路径。选择现有材料保留项目和文件，不发送对话消息、不启动生成。

会话搜索控制器在发送后保留选中的联网或深度模式；后续每次提交仍单独取得授权并附带标记。明确关闭后停止为未来消息授权搜索，重排模式继续禁用搜索。偏好只保留在当前挂载的会话控制器，刷新后恢复关闭。选中模式本身不启动任务，也不授权付费重试。

## 考虑过的替代方案

**每次失败后更换项目。** 丢失与已有上传、草稿和结果的关联，却没有解决查询计划失败。

**自动重试研究或放宽校验。** 在没有新用户决定的情况下重复付费工作，或接受无效查询。

**让消息之间复用搜索授权。** 混淆持续显示的偏好与某次提交的权限；每条消息继续独立准入。

## 后果

没有研究来源的失败可在同一项目改用上传材料继续。已保留来源的研究需要单独决定保留和补充方式。材料解析失败与研究计划失败继续分别处理；本改动不放宽来源、额度、模板或页图审核，不修改数据库结构或迁移业务数据。

定向检查覆盖三项后端、九项MCP、十八项恢复客户端及五项搜索控制器场景，没有真实模型或云调用。客户端构建通过；基线与候选各保留四十九行既有类型诊断，不把全量类型检查报告为通过。真实付费生成和外层聊天Agent流程仍需单独验证。
