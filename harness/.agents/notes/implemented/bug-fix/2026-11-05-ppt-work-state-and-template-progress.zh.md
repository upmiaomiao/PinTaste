# Agent Note: 工作状态与模板解析进度

Status: implemented

[English](2026-11-05-ppt-work-state-and-template-progress.md) | 中文

## 问题

已接受的重试可以与先前未完成草稿并存，旧对话投影却将该活动任务标成失败。私人模板也停留旧上传快照，解析完成却无预览的文件会一直显示解析中。实际iframe要求5张预览，而公开选择规则要求4张。

## 决策

当前任务明确活动时优先于旧未完成草稿；当前任务真实失败和传输错误仍为失败。研究进度保留既有专用标签。失败对话行描述当时记录，并引导查看当前工作详情，不改写历史。

实际iframe产物使用SHA锁定转换器更新，不用旧React源覆盖已发布行为。私人模板明确区分解析完成但无预览的终态。上传页不会显示旧库模板的预览或确认目标。上传视图可见时最多自动读取120秒或30次，终态停止，旧项目计时器不能继续请求。隐藏和释放的视图不派发读取。解析较慢时提示手动刷新，不无限显示等待。

库模板确认要求4张已加载预览和来源参考充足标志，私人模板要求1张已加载预览。仍需用户点击及后端归属、版本、模板校验。材料或需求变化使旧草稿失效时明确解释，不提交新阅读任务或复用已擦除来源。

## 考虑过的替代方案

**将任何未完成草稿视为当前任务结果。** 草稿有效性和任务执行是独立事实，该方案会把排队或运行重试误报为失败。

**无限刷新或离开视图后继续刷新。** 会浪费请求并让旧回调影响后续项目；限定可见视图的读取可以明确归属和释放。

**只凭预览数量启用确认。** 4张图片不等于拥有足够可用来源参考，原有后端规则及卡片参考充足标志继续必需。

**重建旧iframe源。** 旧源缺少当前材料、研究及语言行为；在基线统一前，SHA锁定修改可以保留其他已发布行为。

## 后果

仅改变显示和只读刷新，不改变生成同意或费用。历史失败记录继续可见，较慢或失败的解析仍需明确用户操作。材料擦除及阅读缓存失效沿用[既有删除语义](../feature/2026-11-05-ppt-material-capacity-and-deletion.zh.md)。

无密钥Tool状态回放覆盖排队/运行重试、真实失败和研究标签。实际SDK iframe浏览器场景覆盖中英文、自动完成、无预览、四页库模板及单页私人模板确认条件和窄屏。计时器检查覆盖切项目、可见性、释放及有界轮询。上述检查不需要模型请求。
