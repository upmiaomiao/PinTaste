# Agent Note: PPT需求来源与失败反馈

Status: implemented

[English](2026-11-08-ppt-requirements-source-feedback.md) | 中文

## 问题

更新可能在来源检查阶段失败，需求记录尚未保存任何修改。若所有更新失败都显示为同步未完成，就会错误暗示本次修改已经保存。模型也可能使用了正确的用户消息标识，却释义确认内容或引用工具结果，因而被原有逐字证据检查拒绝。

## 决定

读取工具返回最新已接受的用户消息标识和有界原文字面摘录。摘录最多2000个UTF-16单元，末尾不会保留半个代理对。工具指引要求使用原文，并在新用户回复后重新读取。只有source kind为user的已接受user/message事件可以提供用户来源，工具、助手和插件消息不会成为用户来源。

客户端仅将单一且完全相等的固定工具错误码映射为本地化的来源、冲突、格式或待投影反馈。来源、冲突和格式失败不声称本次修改已保存；待投影反馈区分保存需求与同步项目；未知或混合错误要求读取当前记录，不猜测保存结果、不显示原始错误。历史失败卡仍保留失败状态，恢复沿用明确的读取操作。

## 考虑过的替代方案

**将所有更新失败都视为待同步。** 来源与版本检查可能在保存之前失败，因此会错误说明本次修改的保存结果。

**将工具答复当作用户来源。** 工具结果不能证明已接受的用户来源，既有来源选择器和逐字证据检查仍然是准入依据。

**显示原始错误文本。** 固定且由语言字典管理的分类可以说明下一步，而不暴露任意运行时文本。

## 后果

无密钥标准Loader夹具使用真实Agent、Session、ToolRuntime错误和React渲染，验证逐字证据、旧标识、释义、插件拒绝、新接受的用户回复、摘录边界和双语固定错误反馈。来源选择器和逐字证据guard逐字节保持一致。单独的工具结果不构成已接受的用户回复；本项不改变ask-user桥接、不自动重试更新、不代写原用户失败修改，也不批准生成。
