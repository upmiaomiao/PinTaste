# Agent Note: 私人上传模板进入模板库

Status: implemented

[English](2026-11-05-private-upload-template-library.md) | 中文

## 问题

已上传模板可在原项目使用，却不出现在全部模板中。公共目录、收藏的原生设计和项目上传记录原先分别读取。

## 决策

项目上传模板现在进入所属账号的列表与推荐。全部来源、我的模板和公共模板在分页前筛选。仅投影解析完成且原文件和预览仍存在的模板。SQLite直接选取元数据，不把来源正文或片段读入模板库。私人预览只允许所属账号读取，其他管理员也不能越权访问。

在原项目确认时使用已有材料；在其他自有项目确认时，明确创建原件和代表页的独立副本。工作流事务绑定复制的材料，默认跟随其视觉风格。正文、证据和来源图不会进入内容计划。原有人工确认、版本与容量检查继续有效。HTTP请求事务回滚后清理本次新建文件。

实际iframe通过SHA锁定转换器修改，保留已有语言和材料管理行为。[工作状态与解析进度决策](2026-11-05-ppt-work-state-and-template-progress.zh.md)仍然有效。

## 考虑过的替代方案

**公开上传模板。** 会把私人资料暴露给其他账号。

**上传时自动复制到另一存储。** 删除项目材料后仍可能隐藏保留原件。

**直接引用其他项目的文件。** 原件删除后复用项目会损坏，明确创建独立副本可让文件生命周期可见。

## 后果

无需数据库结构变更、模型调用或云端写入。模板库反映现有项目记录。删除最后一份明确保留的副本后，上传模板从库中消失；删除某项目不会擦除其他项目中明确复用的独立副本。已生成PPT沿用既有删除语义。复制期间进程突然终止仍可能留下未引用文件；常规事务失败在请求结束后清理。

隔离后端检查覆盖账号隔离、路径与哈希、确认绑定、来源筛选与分页、副本独立性、容量拒绝和回滚清理。界面检查使用实际SDK iframe消息，覆盖中英文和窄屏。
