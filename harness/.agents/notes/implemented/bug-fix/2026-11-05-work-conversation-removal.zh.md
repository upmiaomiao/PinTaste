# Agent Note: 工作会话可见删除入口

Status: implemented

[English](2026-11-05-work-conversation-removal.md) | 中文

## 问题

工作会话只有悬浮菜单里的归档操作，空白会话连菜单也没有。Router 还拒绝既有归档 RPC。整合工作历史未读取既有归档集合，导致被移除的行可能在另一个入口重新出现。

## 决策

每条会话常显本地化垃圾桶按钮；它与原 Archive 操作都先确认并说明保留边界。取消和 Escape 不变更数据，失败保留确认框以便重试。运行中任务、运行中的后代、待处理交互或活动定时任务禁用删除。确认沿用既有持久化 workspace 归档集合及当前选择清理，不擦除对话日志、PPT、材料或用量，不取消已提交任务。

原 session/list 请求增加可选布尔字段 `excludeArchived`，只有浏览调用方主动启用。列出授权摘要后再读取当前 workspace 归档集合过滤。测试 Router 工作历史启用该过滤，运行任务读取保持默认完整列表。Router 允许集合仅补入既有归档 RPC：request 仅接收一个合法 sessionId，通过认证账号独有的 Host registry 执行；其他工作区管理及可选 RPC 仍受限制。没有新原生 RPC 或结构迁移。

原全局归档存储决策保持，本记录仅替代其旧版无需确认的 UI 决策。部分检出的完整 Typert 生成因找不到 Remote 方法而失败。仓库内 SHA 锁定的元数据复现器只给既有 Host/Client 请求 codec 增加可选布尔字段，解码测试覆盖两份实际发布 codec，其余元数据字节保持。

## 考虑过的替代方案

**永久删除原始记录。** 会擦除保留的工作，需要单独的生命周期决策。

**仅客户端过滤。** 整合历史仍会不一致。

**默认过滤 session/list。** 可能使任务控制读取漏掉归档后仍运行的任务；主动启用保持兼容。

## 后果

移除通过既有 registry 跨刷新保留，目前没有取消归档界面。列表和确认不是原子的任务取消边界，已提交任务继续执行。验证覆盖空白行、取消、失败重试、活动状态限制、过滤竞态、严格协议、Router 归属边界及双语真实组装界面。真实移除验收仅使用新建夹具，不调用模型，不移除原有记录。
